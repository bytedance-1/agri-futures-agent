# 商品期货波段交易助手（云端自动运行）

面向**上班族、不盯盘、做周内波段**的商品期货组合交易助手（11 个主力连续品种）。
盘后自动算信号、盘中自动盯持仓，结果直接推送到微信；全部逻辑跑在 **GitHub Actions**（免费云端），
无需自己买服务器，定时任务已随仓库配好。

> 本系统只做**信号计算与提醒**，不会、也不能替你自动下单。你只需在交易软件里按推送的
> “条件单”参数挂单即可（详见下文「如何挂单」）。

---

## 一、它每天为你做什么

| 时间（北京时间） | 脚本 | 干什么 |
| --- | --- | --- |
| 交易日 15:10（周一~周五） | `daily_signal.py` | 拉取全品种当日行情 → 算信号 → 生成次日**挂单价/止损/止盈/手数** → 推送微信表格 |
| 交易日 9:30-15:00 每 30 分钟 | `position_monitor.py` | 读取持仓 → 抓实时价 → 判断止损/止盈/到期/**周末节前强平** → 自动更新持仓并推送提醒 |

两个任务都由 [`.github/workflows/`](.github/workflows) 下的定时任务自动执行，**无需你手动配置**。

**交易品种（11 个主力连续）**：螺纹钢 RB、锰硅 SM、甲醇 MA、纯碱 SA、豆粕 M、玉米淀粉 CS、
鸡蛋 JD、花生 PK、白糖 SR、苯乙烯 EB、苹果 AP。

## 二、交易规则（当前 config.json 参数）

### 1. 入场（必须在“同时满足”以下条件时才产生信号）

| # | 条件 | 说明 |
| --- | --- | --- |
| ① | 当日成交量 ≥ 20日均量 × **1.4** | 量能必须放大 |
| ② | 当日成交量处于近 60 日的 **60% 分位以上** | 在量能放大的基础上再保证是“历史级放量” |
| ③ | 当日持仓量增量 ≥ 20日持仓增量均线 × **1.4**，且为正 | 增仓上涨/增仓下跌，资金真进场 |
| ④ | K线实体涨跌幅 ≥ **0.6%** | 强实体，过滤十字星/长影线 |
| ⑤ | 20日 ATR ≥ 20日 ATR 均线 × **0.9** | 波动率处于扩张状态才交易 |
| ⑥ | 收盘价在 20日均线上方 → 只做多；下方 → 只做空 | 顺势 |

### 2. 挂单价与出场

| 项目 | 多头 | 空头 |
| --- | --- | --- |
| 挂单价（条件单触发价） | 当日最高价 **+1** | 当日最低价 **-1** |
| 初始止损 | 挂单价 − **1.5 × ATR20** | 挂单价 + **1.5 × ATR20** |
| 第一止盈 | 挂单价 + **1.5 × ATR20** | 挂单价 − **1.5 × ATR20** |
| 第二止盈 | 挂单价 + **2.5 × ATR20** | 挂单价 − **2.5 × ATR20** |
| 时间止损 | 持仓满 **4** 个交易日未到止盈 → 平仓 | 同 |
| 周末/节前强平 | 距下一交易日 ≥ 3 天的当日 **14:30 之后**，市价平掉所有持仓，持仓不过周末/节假日 | 同 |

- 第一止盈触发后：**平 60% 仓位**，剩余仓位**止损上移到保本**；
  若只有 1 手无法部分止盈，则**止损上移保本并继续持有**博第二止盈。
- 第二止盈触发：**全部平仓**。

### 3. 仓位与组合管理

- 本金默认 **20000 元**，单笔最大亏损 **5%**（1000 元），按“亏损 ÷ 单手止损额”倒推手数；
- 单品种保证金 ≤ 总资金 **40%**；
- 最小 1 手保护：当风险测算为 0 手、但 1 手风险 ≤ 8%（硬上限）且保证金 ≤ 60% 时，允许开 1 手；
- **同方向多个信号只保留“成交量放大倍数”最高的 1 个**；
- 组合约束（相关性）：`RB-SM`、`MA-SA`、`MA-EB`、`M-CS` 不得同时持有；
- 最多同时 **6** 个持仓；
- 止损离场后进入 **2 个交易日冷却期**，避免连续挨打。

## 三、回测结果与说明

回测脚本 `backtest.py` 会按**日线历史**逐品种模拟“信号 → 次日挂单成交 → 止损/止盈/时间止损”，
并与一组更宽松的“原始对照参数”对比（`python backtest.py` 可复现）。

**组合级回测**（11 品种主力连续，2023-01 ~ 2026-10，约 900 个交易日，含手续费+滑点，
按 live 的选择逻辑——最大持仓数 + 相关性约束 + 冷却 + 周内强平——滚动模拟）：

| 指标 | 数值 |
| --- | --- |
| 交易笔数 | 169（约 47 笔/年） |
| 胜率 | 53% |
| 总盈亏 | +15548 元（对 2 万本金约 +78%） |
| 盈亏比 | 1.47 |
| 最大回撤（已实现权益） | 4331 元 ≈ **21.7%** |
| 最大回撤（含浮动日权益） | 2500 元 ≈ **12.5%** |

> **必须诚实说明的两点**：
> 1. 这是**中频策略**：样本期内约 47 笔/年，组合分散后统计意义尚可，但回测收益不代表未来，
>    实盘应以小仓位验证；
> 2. 日线回测只能近似盘中路径，结果存在偏差。**请把回测当作“规则是否合理”的验证，而非收益承诺**。

## 五、部署步骤（唯一需要你动手的是第 3 步配置推送 key）

1. **仓库已创建**：代码已推送，无需改动。
2. **确认 Actions 已开启**：仓库 → Settings → Actions → General → 允许运行（通常默认开启）。
3. **配置微信推送密钥**（三选一，推荐 Server酱³）：
   - 打开 <https://sct.ftqq.com>，用微信扫码登录，复制你的 **SendKey**；
   - 回到仓库 → Settings → Secrets and variables → Actions → New repository secret；
   - Name 填 `SERVERCHAN_SENDKEY`，Value 粘贴 SendKey，保存。
   - （可选）如需同时用 PushPlus / 企业微信，追加 `PUSHPLUS_TOKEN` / `WECOM_WEBHOOK`。
4. **手动验证一次**：仓库 → Actions → 选 `daily-signal` 或 `position-monitor` → Run workflow。
   微信收到消息即表示打通。

## 六、如何挂单（关键：用“条件单”，不是普通限价单）

因为挂单价在“现价的上方/下方”（突破入场），普通限价单会**立刻成交**，必须用**条件单/停损单**：

- **多头**：设置“价格 ≥ 挂单价 触发 → 买入开仓 N 手”；
- **空头**：设置“价格 ≤ 挂单价 触发 → 卖出开仓 N 手”；
- 挂单**仅次日有效**，未触发则自动作废（系统会推送“挂单失效”）。

> 各期货公司软件里叫法不同：条件单 / 止损单 / 触价单 / 预埋单，找交易软件里的“条件单”功能即可。

## 八、常见问题

- **收不到推送？** 检查 `SERVERCHAN_SENDKEY` 是否配置正确；Server酱需先在微信里关注其公众号。
- **执行时间不准？** GitHub Actions 的 cron 高峰期可能延迟几分钟到十几分钟，属正常；对分钟级精度要求高可自建 cron 调用。
- **会不会自动停？** GitHub 对**长期无提交**的仓库会暂停定时任务；本系统每次运行都会回写 `position.json`，持续有提交，不会触发。
- **长假如休市日怎么维护？** 系统会**在线自动获取**今年/明年的法定休市日（`common.market_holidays`），
  失败时回退到 `config.json` 的 `holidays` 列表；跨年时该列表会自动更新，无需手动维护。
- **想换品种/改参数？** 直接编辑 `config.json`，无需改代码。`margin_rate` 请按你期货公司实际保证金比例调整（常见 10%~13%）。
- **资金与手数**：部分品种（如苹果 AP）单手保证金较高，在 2 万 + 40% 上限下可能测算为 0 手而不开仓，
  属正常的风控结果；若想覆盖更多品种，可提高本金或 `max_margin_ratio`。

## 九、风险提示与免责声明

- 本系统输出的是**机械规则的计算结果，不构成任何投资建议**；
- 期货为杠杆交易，风险极高，可能损失超过本金，请务必使用**可承受损失的资金**；
- 数据来自新浪财经免费接口，可能存在延迟、缺失或错误，实盘前请自行核对；
- 回测基于历史数据，**过往表现不代表未来收益**，请先小仓位实盘验证后再逐步加码。
