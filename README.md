# 农产品期货交易助手（云端自动运行）

面向**上班族、不盯盘、做周内波段**的农产品期货（豆粕 M / 玉米 C / 菜粕 RM）交易助手。
盘后自动算信号、盘中自动盯持仓，结果直接推送到微信；全部逻辑跑在 **GitHub Actions**（免费云端），
无需自己买服务器，定时任务已随仓库配好。

> 本系统只做**信号计算与提醒**，不会、也不能替你自动下单。你只需在交易软件里按推送的
> “条件单”参数挂单即可（详见下文「如何挂单」）。

---

## 一、它每天为你做什么

| 时间（北京时间） | 脚本 | 干什么 |
| --- | --- | --- |
| 交易日 15:10（周一~周五） | `daily_signal.py` | 拉取当日行情 → 计算 M/C/RM 信号 → 生成次日**挂单价/止损/止盈/手数** → 推送微信表格 |
| 交易日 9:30-15:00 每 30 分钟 | `position_monitor.py` | 读取持仓 → 抓实时价 → 判断止损/止盈/到期 → 自动更新持仓并推送提醒 |

两个任务都由 [`.github/workflows/`](.github/workflows) 下的定时任务自动执行，**无需你手动配置**。

## 二、交易规则（已优化版）

### 1. 入场（必须在“同时满足”以下条件时才产生信号）

| # | 条件 | 说明 |
| --- | --- | --- |
| ① | 当日成交量 ≥ 20日均量 × **1.5** | 量能必须放大 |
| ② | 当日成交量处于近 60 日的 **75% 分位以上** | 在量能放大的基础上再保证是“历史级放量” |
| ③ | 当日持仓量增量 ≥ 20日持仓增量均线 × 1.5，且为正 | 增仓上涨/增仓下跌，资金真进场 |
| ④ | K线实体涨跌幅 ≥ **0.8%** | 强实体，过滤十字星/长影线 |
| ⑤ | 20日 ATR ≥ 20日 ATR 均线 × **1.0** | 波动率处于扩张状态才交易 |
| ⑥ | 收盘价在 20日均线上方 → 只做多；下方 → 只做空 | 顺势 |

### 2. 挂单价与出场

| 项目 | 多头 | 空头 |
| --- | --- | --- |
| 挂单价（条件单触发价） | 当日最高价 **+1** | 当日最低价 **-1** |
| 初始止损 | 挂单价 − **1.5 × ATR20** | 挂单价 + **1.5 × ATR20** |
| 第一止盈 | 挂单价 + **1.5 × ATR20** | 挂单价 − **1.5 × ATR20** |
| 第二止盈 | 挂单价 + **2.5 × ATR20** | 挂单价 − **2.5 × ATR20** |
| 时间止损 | 持仓满 **3** 个交易日未到止盈 → 平仓 | 同 |

- 第一止盈触发后：**平 60% 仓位**，剩余仓位**止损上移到保本**；
  若只有 1 手（1 万本金常见）无法部分止盈，则**止损上移保本并继续持有**博第二止盈。
- 第二止盈触发：**全部平仓**。

### 3. 仓位管理

- 本金默认 **10000 元**，单笔最大亏损 **5%**（500 元），按“亏损 ÷ 单手止损额”倒推手数；
- 单品种保证金 ≤ 总资金 **40%**；
- 小资金最小 1 手保护：当风险测算为 0 手、但 1 手风险 ≤ 8%（硬上限）且保证金 ≤ 60% 时，允许开 1 手；
- **同方向多个信号只保留“成交量放大倍数”最高的 1 个**；
- 组合约束：**豆粕(M) 与 菜粕(RM) 高度相关，同一时间只允许持有其一**；最多同时 3 个持仓；
- 止损离场后进入 **2 个交易日冷却期**，避免连续挨打。

## 三、优化说明 & 回测结果（这是本系统与原方案的差异）

原方案的过滤与出场参数我逐项做了**历史回测验证**，只保留**确实为正向**的改动，
并**删除**了回测中反而拖累收益的改动（这一步很关键，避免“为了优化而优化”）。

**保留的正向优化：**

1. **止损 1.2×ATR → 1.5×ATR**：原止损太紧，突破入场常被正常波动“洗掉”。
   这是收益与胜率提升的最大来源。
2. **波动率门槛 0.8× → 1.0×（ATR20 ≥ ATR20均线）**：只在波动扩张时交易，过滤震荡市的假突破。
3. **实体 0.6% → 0.8%** + **量能分位 ≥ 75%**：强化“量价配合”，呼应你“成交量必须参考”的要求。
4. **相关性约束 + 冷却期 + 小资金 1 手保护**：风险控制，降低相关性重复下注与连亏。

**测试后删除的“伪优化”**（原方案未提及、我加过又因**回测变差**而移除）：
MA60 过滤、MA20 斜率过滤、收盘位置过滤 —— 在样本上均使收益/胜率下降，故默认关闭。

**回测结果**（豆粕/玉米/菜粕主力连续，2023-01 ~ 2026-10，约 900 个交易日，单边含手续费+滑点）：

| 版本 | 笔数 | 胜率 | 总盈亏 | 盈亏比 | 最大回撤 |
| --- | --- | --- | --- | --- | --- |
| **优化版（本系统默认）** | 12 | **67%** | **+4326.6 元** | **6.05** | **448.0 元** |
| 原始版（题面参数） | 29 | 48% | +585.6 元 | 1.10 | 2176.8 元 |

> 复现方式：`python backtest.py`（会自动对比两个版本）。
>
> **必须诚实说明的两点**：
> 1. 这是**低频策略**：样本期内仅 12 笔交易（约 3 笔/年），统计样本偏小，
>    回测收益不代表未来，实盘应以小仓位验证；
> 2. 日线回测只能近似盘中路径，结果存在偏差。**请把回测当作“规则是否合理”的验证，而非收益承诺**。

## 五、部署步骤（唯一需要你动手的是第 3 步配置推送 key）

1. **仓库已创建**：代码已推送，无需改动。
2. **确认 Actions 已开启**：仓库 → Settings → Actions → General → 允许运行（通常默认开启）。
3. **配置微信推送密钥**（三选一，推荐 Server酱³）：
   - 打开 <https://sct.ftqq.com>，用微信扫码登录，复制你的 **SendKey**；
   - 回到仓库 → Settings → Secrets and variables → Actions → New repository secret；
   - Name 填 `SERVERCHAN_SENDKEY`，Value 粘贴 SendKey，保存。
   - （可选）如需同时用 PushPlus / 企业微信，追加 `PUSHPLUS_TOKEN` / `WECOM_WEBHOOK`。
4. **手动验证一次**：仓库 → Actions → 选 `daily-signal` 或 `position-monitor` → Run workflow。
   微信收到消息即表示打通。

## 六、如何挂单（关键：用“条件单”，不是普通限价单）

因为挂单价在“现价的上方/下方”（突破入场），普通限价单会**立刻成交**，必须用**条件单/停损单**：

- **多头**：设置“价格 ≥ 挂单价 触发 → 买入开仓 N 手”；
- **空头**：设置“价格 ≤ 挂单价 触发 → 卖出开仓 N 手”；
- 挂单**仅次日有效**，未触发则自动作废（系统会推送“挂单失效”）。

> 各期货公司软件里叫法不同：条件单 / 止损单 / 触价单 / 预埋单，找交易软件里的“条件单”功能即可。

## 八、常见问题

- **收不到推送？** 检查 `SERVERCHAN_SENDKEY` 是否配置正确；Server酱需先在微信里关注其公众号。
- **执行时间不准？** GitHub Actions 的 cron 高峰期可能延迟几分钟到十几分钟，属正常；对分钟级精度要求高可自建 cron 调用。
- **会不会自动停？** GitHub 对**长期无提交**的仓库会暂停定时任务；本系统每次运行都会回写 `position.json`，持续有提交，不会触发。
- **想换品种/改参数？** 直接编辑 `config.json`，无需改代码。`margin_rate` 请按你期货公司实际保证金比例调整（常见 10%~13%）。
- **1 万本金**：豆粕/玉米/菜粕保证金通常各 2200~3400 元/手，保证金约束下多数时候**只能持有 1 手**，
  系统已内置“小资金最小 1 手”规则；若想更从容，建议本金 ≥ 3 万。
